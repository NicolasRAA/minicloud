Гонка 2. Телефон загружает фото, которое уже есть в облаке, а корзина в это время
удаляет навсегда старую копию этого фото (последний файл с тем же содержимым)
==============================================================================
Наивно (как в ПР3): «Загрузка» только спрашивает, есть ли содержимое; привязку делает
подписчик UploadCompleted позже.
  1. Загрузка: содержимое найдено, загрузка-дубликат сразу завершена, байты не передавались
  2. FilePurged старого файла: содержимое удалено, байты уйдут из S3
  3. Подписчик UploadCompleted: ошибка внешнего ключа, содержимого больше нет
  Итог: загрузка завершена, «Файлы» покажут файл доступным, а байтов нет ни в базе, ни в S3.
        Повтор задачи не поможет. Это и есть «мы их утеряли» из отзыва R41.

С исправлением, порядок А: привязка дубликата успела первой.
  FilePurged ждёт в очереди за строкой содержимого
  Привязка: файл b86dfffe… хранит байты в содержимом 00000000…
  FilePurged: содержимое осталось: на него ссылается дубликат

С исправлением, порядок Б: удаление навсегда успело первым.
  Привязка ждёт в очереди за строкой содержимого
  FilePurged: содержимое удалено, байты уйдут из S3
  Привязка: дубликата нет, телефон передаёт байты как при обычной загрузке
  Итог в обоих порядках: файла без байтов не бывает.

Нагрузка: 100 загрузок по 200 МиБ стартуют одновременно, выделено 10 ГиБ (10 240 МиБ)
==============================================================================
  Пауза 5 мс между чтением и записью изображает работу кода между ними.
  наивно         принято 100 из 100, строк резерва на  20000 МиБ, счётчик    400 МиБ,   227 мс
  FOR UPDATE     принято  51 из 100, строк резерва на  10200 МиБ, счётчик  10200 МиБ,   811 мс
  FOR UPDATE, 0  принято  51 из 100, строк резерва на  10200 МиБ, счётчик  10200 МиБ,   240 мс
  Предел: 10 240 // 200 = 51 загрузка. С блокировкой принято ровно 51, счётчик сходится со строками.
  Под блокировкой резервы идут по очереди, поэтому время растёт с длиной транзакции:
  в строке «FOR UPDATE, 0» паузы нет, так будет в коде, где между чтением и записью нет S3.
